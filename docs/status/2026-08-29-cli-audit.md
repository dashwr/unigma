# auditoria — CLI Rust após a retirada do Agent Host (2026-08-29)

> **tipo:** auditoria somente-leitura. Nenhum arquivo de código foi alterado
> durante o levantamento.
>
> **motivo:** a onda 1 de [`../planos/2026-08-28-ondas-refundacao.md`](../planos/2026-08-28-ondas-refundacao.md)
> removeu o Agent Host do workbench, do build e dos testes TypeScript, mas não
> tocou em `cli/`. Antes de continuar o corte era preciso saber o que, dentro do
> CLI, o SSH remoto ainda precisa.
>
> **consequência:** plano [`../planos/2026-08-29-cli-ssh-remoto.md`](../planos/2026-08-29-cli-ssh-remoto.md).

## pergunta

O Code Server do CLI é resíduo do Agent Host herdado ou é infraestrutura
necessária ao SSH remoto?

## resposta

É **necessária**. O SSH remoto exige um servidor Code - OSS no host remoto para
hospedar o extension host que, por sua vez, hospeda o `unigma-agent-runtime` e o
`opencode serve`. O `opencode serve` não substitui esse servidor.

## preservar

| caminho | papel |
| --- | --- |
| `cli/src/tunnels/code_server.rs` | resolve, baixa, instala, inicia por socket ou porta, aguarda `Extension host agent listening on ...` e controla o ciclo de vida do servidor |
| `cli/src/tunnels/server_bridge.rs` | conecta ao servidor iniciado |
| `cli/src/tunnels/server_multiplexer.rs` | multiplexa mensagens para o cliente |
| `cli/src/tunnels/protocol.rs` | mensagens do control server |
| `cli/src/tunnels/control_server.rs` (RPC genérico: `serve`, `fs_*`, `net_connect`, `spawn*`, `servermsg`, `callserverhttp`) | superfície usada pelo cliente remoto |
| entry point `command-shell` | ponto de entrada que o transporte SSH usa |

## observações de fato

- `constants::PROTOCOL_VERSION` está em `6`; a documentação do próprio arquivo
  registra que os níveis `5` e `6` existem **apenas** por causa da capacidade de
  agent host. Valor final após a remoção é decisão aberta.
- `constants::SERVER_DATA_PARENT_DIR` continua em uso legítimo por
  `cli/src/state.rs`; apenas o comentário menciona o supervisor removido.
- `product.json` define `serverApplicationName: "unigma-server"` e
  `serverDataFolderName: ".unigma-server"`, mas **não** define `updateUrl`,
  `downloadUrl`, `quality` ou `commit`. O download automático do servidor por
  `UpdateService` não tem endpoint neste fork.
- `extensions/unigma-remote-ssh/` contém somente `src/remoteSshPolicy.ts`, a
  política pura de `T-013`. Não existe transporte, autoridade remota, resolução
  de alvo nem provisionamento de servidor.
- No TypeScript, os únicos resíduos de agent host fora de documentação são as
  completions de `terminal-suggest` e nomes de variáveis locais em testes de
  `sessions`/`chat` sem relação com o subsistema.
